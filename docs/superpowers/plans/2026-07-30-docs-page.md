# Docs Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a public `/docs` page covering API-key setup, event ingestion, and outbound webhooks with real code samples, plus a link to the existing Swagger reference — per `docs/superpowers/specs/2026-07-30-docs-page-design.md`.

**Architecture:** `frontend/src/routes/DocsPage.tsx`, mounted unconditionally at `/docs` in `App.tsx` (public regardless of auth state, unlike `/`'s `HomeRoute`). Single scrollable page, sticky in-page table of contents, four anchored sections. `LandingPage.tsx`'s header gets a "Docs" link.

**Tech Stack:** React 19 + TypeScript strict, React Router, Tailwind v4 (existing Alexandria tokens), Vitest + Testing Library.

## Global Constraints

- Every field name, header name, and payload shape must match the real backend implementation exactly — cross-check `backend/src/flowsage_backend/deps.py`, `api/events.py`, `integrations/webhooks.py`, `models/webhook.py`, `worker.py`, `rate_limit.py` at implementation time, not just the spec's copy.
- Reuse existing Alexandria design tokens — no new fonts/colors.
- `/docs` is public for both logged-in and logged-out visitors — no `RequireAuth`, no redirect logic.
- `npx oxlint`, `npm run typecheck`, `npm test`, `npm run build` must all stay clean.
